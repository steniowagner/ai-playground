# Production Access Policy

## Least privilege

Production access is granted only when required for an employee's current responsibilities. Read and write privileges are separate. Standing write access is limited to designated platform and reliability roles; other write access must be time-bound.

## Request process

The requester must submit an access ticket naming the systems, permission level, business justification, and requested duration. Approval is required from the requester's manager, the system owner, and Information Security. Database administrator approval is additionally required for production database access.

## Prerequisites

Before access is activated, the employee must complete current security training, enroll a phishing-resistant MFA method, use a company-managed device, and acknowledge the acceptable-use conditions. Access must be issued through an individual identity; shared accounts are prohibited.

## Emergency access

Emergency break-glass access may be used only to mitigate an active incident when normal approval would cause material harm. The user must state the incident identifier, and the access expires after two hours. Security and the system owner review all break-glass activity by the next business day.

## Review and removal

System owners review access quarterly. Access is removed immediately upon role change, termination, loss of business need, or policy violation. Production activity is logged and may be audited.
